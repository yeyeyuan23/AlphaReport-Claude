# 统一业务流程

## 已确认的目标

根据本次七组重复流程审计，用户要求依次修复重复实现和两套系统并存。
保留机器人功能、CLI 参数、研报阅读接口和研究方向明细。用户后续明确仅使用飞书机器人，并确认删除 legacy_app；旧网页聊天与任务 API 下线。
同一任务只有一个执行、校验和保存实现；不通过移除用户功能来掩盖重复。

## 统一边界

1. 采集以 `services.collection` 为准。CLI、定时任务与机器人调用的采集共用它；
   删除旧 Graph 及其专属 collect/classify/filter/analyze/store 节点，旧网页聊天与采集 API 不再保留。
   精确时间、目录、进度和取消要求传入同一服务；已保存的部分结果不伪装为回滚。
2. 摘要相关性由 `paper_scoring` 统一。全方向分数保留为详细模式，统一模型协议、材料与
   规则指纹及 selection 字段，新明细不再存入 analysis_json；失败不覆盖成功。
3. 库内分析由 `batch_analysis` 执行，`AnalysisAgent` 是唯一阶段引擎。批量服务统一处理进度、取消、输入、完整性和并发保护。单篇 PDF 的版本、产物和投递政策仍保留。
4. 摘要生成共用 summary skill、提示构造与执行，区分已有分析和原文输入；
   下线旧聊天与 SSE 的专属生成及持久化代码。问答类任务不伪装为完整分析。
5. PDF 获取复用现有下载策略与 `report_pdf` 缓存；公共文字提取、MinerU 回退只保留一份。
   本地结构化解析的 Docling 合并是策略参数。维护 CLI 保存重新查询当前记录、校验材料并
   失效派生产物，不能提交 detached 对象或静默报告保存成功。
6. 飞书统一客户端、发送请求、结果校验和分片。日报/周报保留各自模板、收件人和运行记录；
   共用投递能力，文本回退和消息 ID 校验保持一致，保留单篇 UUID。
7. WebSocket 与 HTTP inbox 先规范化事件，再共用鉴权、会话快照、命令、线程和回复处理。
8. Web 只保留 main.app。删除 legacy_app、旧聊天框架、任务 API 及其无人调用的配置/依赖，主应用继续提供机器人消息中的论文详情与 PDF。

## 约束与验收

- Python 3.12，无新增依赖，不改密钥、系统调度和外部服务；自动测试隔离真实数据库。
- 服务保持停止；不调用真实模型、不发送飞书、不用电脑控制。
- 每步先写失败回归再实现；临时数据库、MockTransport 和模型边界替代用于测试。
- 验收包含跨入口同输入/同政策、低相关不入库、缺材料与模型失败、并发修改、取消、
  模型失败不发成功、消息分片/回退失败和旧入口下线。
- 最后运行全量 Python、Ruff、前端已有检查、shell 语法及 diff 检查。

## 不合并的合理差异

日报与周报日期窗口、单篇与批量分析 profile、结构化分析与研究质量评估、启动增量导入
的文件指纹和锁、卡片模板、同步/异步 HTTP 桥接继续保留，复用它们的公共执行能力。
