# AlphaReport

在飞书里查找、阅读和讨论量化金融研报，接收日报与周报；网页用于检索资料、阅读 PDF 和核对分析依据。Python 服务与 Claude Code 运行在自己的电脑或服务器上，模型推理通过 API 完成。

## 功能与使用

### 在飞书中聊天

直接发送普通文本即可连续讨论研报，也可以提出查找、比较、分析或整理资料的要求，例如：

```text
找出库中和波动率预测有关的论文，比较它们的数据、方法与局限。
重新分析刚才讨论的那篇论文，缺失信息注明未报告。
为这篇论文整理复现前需要核对的数据、划分、基准和指标。
生成一份周报预览，先不要发送。
```

这些是交给 Claude Code 理解的请求。它通过已有的共享 CLI 查询资料、解析标题与上下文对应的记录，再执行相应处理；用户不需要查找或填写数据库内部 ID。能否执行取决于运行账户的 Shell/文件工具权限与可用资料，不能把普通聊天理解为固定命令或保证成功的自动操作。

普通聊天每次调用上限 **300 秒**，长回复完整分段发送；短提示使用纯文本，含标题、链接或代码的回复使用卡片，表格转为逐项字段。同一会话的问题按接收顺序处理，不同会话可并行。每个 `chat_id` 独立保存会话，群内共用该群的会话；能收到哪些群消息取决于飞书订阅权限，代码没有强制“必须 @ 才处理”的过滤。

### 已有快捷命令

在允许名单内的私聊或群聊使用以下命令；单篇、日报和周报命令仅限私聊：

| 输入 | 作用 |
|---|---|
| `/help`、`/start` | 查看帮助 |
| `/stats` | 查看总研报数、含全文和仅摘要篇数 |
| `/search 因子模型` | 搜索库中研报，最多返回 5 条 |
| `/recent` | 查看最近入库的 5 篇 |
| `/chatid` | 查看当前会话 ID，供部署者配置推送目标 |
| `/clear` | 清除当前会话映射与摘要，不删除研报 |
| `/report 2005.13665` | 分析一篇 arXiv 论文并推送到当前私聊 |
| `/daily` | 汇总昨天公开发布的资料并推送到当前私聊 |
| `/weekly` | 汇总截至昨天的七天公开发布的库中资料并推送到当前私聊 |

`/report` 也接受 `https://arxiv.org/abs/2005.13665v3` 这样的链接，支持现代 arXiv 编号，一次处理一篇。它要求可用 PDF 全文，关键分析阶段缺失时停止发送；分析产物和证据评估同时保存到研报库与 `data/one_reports/`，可从网页查看。

`/clear` 立即切换会话代次，新问题无需等待旧任务；旧任务不能恢复记忆或继续发送尚未投递的回复分片。它不会停止已启动的模型进程，也不会撤销工具操作或已发出的消息。

单个机器人进程内，同一消息 ID 的重复事件不会重复执行已完成的问答或已接受的报告命令。成功结果与发送回执保存在 `data/sessions.db`；投递失败时重试原消息只重发缓存结果，真实模型失败则允许重试。多进程和崩溃窗口不保证全局恰好执行一次。单篇产物对同一会话已有成功回执时不重复发送；顺序重新生成日/周报则会再次发送本期内容。

### 阅读网页

网页提供关键词搜索、市场/资产/频率/主题筛选、统计、分页和 PDF 阅读。详情中的研究简报展示已有分析，“论文速览”展示当前有效的全文评估，包括研究问题、方法、发现、阅读建议及可展开的原文引证。缺少有效评估时显示摘要和待核验状态；“刷新展示”只更新展示，不重做评估。

需要进一步核对论文时，可使用详情中的“复现准备”：从全文整理研究目标、推断时可用信息、训练目标、数据、划分、基准、指标和假设。生成时会调用模型；原文事实附引文，缺失设置列为待核查，最小验证与否定条件标为建议。理论研究核对命题、假设与反例。准备卡不会下载数据或训练模型，也不代表已经复现成功。

分析与全文评估默认覆盖完整提取文本，最多 240,000 字符。自动评估和日/周报直接跳过缺全文、正文不可用或超过该上限的论文，不进入自动补抓队列，不分章节追加阅读，不列为待核验；采集首次下载、解析后才发现超长的，也在此停止后续处理。PDF 提取可能丢失公式、图表；模型阅读评估不代表结论已被独立验证，重要结论仍需对照原文。

来源仅用于追溯与覆盖统计，不作为相关性或质量高低的依据。摘要按启用方向统一评分；有明确量化研究对应任务的通用方法可按迁移相关性入选，无需已有金融实验。全文按内容区分实证、理论、方法、综述或观点，所有来源共用 `quality-rubric.md` 的方法、验证、适用范围、复现细节四项检查，保留逐项判断依据。分析与阅读评估统一使用“较强/基本扎实/较弱/尚不确定”及置信度，不再生成数字总分；未知数据源、代码或适用性保留未知。准则升级后旧缓存失效，后续采集或显式重评后恢复当前结果，旧资料保留。

显式重新生成叙事简报时会发送完整提取文本和已有分析，按研究类型选择结构；不强求公式、实验数字或固定数量的创新点，超过输入上限则保留已有展示。

### 日报与周报

| 报告 | 资料范围 | 运行方式 |
|---|---|---|
| 日报 | 昨天的资料，统一按来源日期 `published_date` 筛选 | 私聊 `/daily`；服务持续运行时，默认每天北京时间 09:00 通过飞书机器人自动推送 |
| 周报 | 截至报告前一天的七个自然日的库中资料，统一按 `published_date` 筛选 | 私聊 `/weekly`；服务持续运行时，默认每周五北京时间 09:00 通过飞书机器人自动推送 |

日报和周报底部附有“研报库首页”链接，使用 `ALPHAREPORT_BASE_URL` 配置的网页地址。

报告只读取已有论文和当前有效的全文评估，不搜索、下载、重新筛选或重新评估论文；周报额外调用配置的 DeepSeek 模型，将每篇已有评估压缩成一句话结论。日报范围是昨天，周报范围是截至昨天的七个自然日，均包含起止日期；08:00 采集和 09:00 推送仅是任务执行时间，不构成日期筛选边界。所有来源只保存一个业务日期 `published_date`，接口和卡片显示 YYYY-MM-DD；不推算或补造时分秒，不以入库日期替代来源日期。本地 PDF 保留有证据的发表日期；只有年/月或未知日期的资料仍可入库阅读，但不进入日/周报。

例如 2026-10-18 执行时，采集和日报只查询 2026-10-17，周报查询 2026-10-11 至 2026-10-17，均不包含 10 月 18 日。日报标题仍标记执行的报告日，正文列明实际资料日期范围。

两种报告读取采集时保存的相关性筛选与全文质量评估，按模板排版。日报重点推荐最多 5 篇；周报按研究方向分组，每篇独立展示一句话结论，下一行放论文标题链接，各篇之间留空行，不加“依据：”前缀，不额外列出重复的推荐清单；待核验项保留在末尾。DeepSeek 为每篇生成目标30～60字的短结论，中英混排尽量控制在160字符内，保留关键适用条件，细节留在论文解读中；个别句子稍长不会导致整份报告回退。模型输出必须逐篇对应，不能遗漏、合并或重复引用。生成失败时提示状态，直接展示已有的简短发现；已有发现过长时保留标题入口并提示查看完整解读，不裁掉条件或堆成长段落。结论不改写论文评估或推荐等级。重点推荐要求当前方向相关性至少 6 分、研究质量必须“较强”、评估把握必须“高”，且没有明确影响核心结论的关键疑虑。“基本扎实”或评估把握为“中”的可读论文归入值得浏览。学术论文、券商研报和社区研究均适用同一推荐门槛，并标明材料类型；其他材料按类型展示；全文可用但评估未完成的条目显示待核验，缺全文或超长的条目直接跳过，不凑推荐数量。

**全文质量评估在采集任务的最后阶段完成，默认不限数量。** `configs/app.yaml` 的 `daily_collection.max_reviews` 省略或设为 `null` 时处理全部符合条件且需更新的论文，正整数启用新评估预算。有效缓存不占预算；缺全文或超长的条目记录跳过数量，不发起补下载或模型调用。材料可用但评估失败、过期或超出预算的条目由后续采集继续处理，报告如实展示待评估。单篇评估限时 240 秒，整批任务不设固定总时限。

没有符合条件的候选时仍明确回复空结果。日报运行产物保存在 `data/daily_reports/`，包含状态、阶段错误与逐收件人发送结果。报告不按逐篇发送历史排除论文；重复执行会再次发送仍符合本期范围的内容。飞书 `/report`、`/daily`、`/weekly` 共用任务锁，同一时间处理一个任务，后台报告任务不占普通聊天的 300 秒调用窗口。

### 后台如何处理资料

在线来源包括 arXiv、东方财富和 BigQuant。每天 08:00 的自动采集与日报共用昨天的来源日期范围，逐页检查窗口内的全部元数据，不设前 15/50 篇或固定页数上限。q-fin 全部保留；扩展的机器学习与优化分类按配置的标题/摘要主题词筛选。先检查来源日期和来源身份，再按启用方向对完整摘要评分；只有达到相关性阈值的论文才分类、入库和下载全文。低相关候选不下载、不保存逐篇元数据或评分，仅累计筛除数量。摘要相关性评分默认每批 10 篇、最多 4 批并行；`push_settings.screening_concurrency` 可设置正整数并发数，设为 `1` 则串行。并发不会改变评分标准或下载门槛。

arXiv 自动采集读取官网按日期分组的最近公告列表，覆盖 q-fin 全部量化金融子分类（含跨分类公告），并按主题扩展 cs.LG、stat.ML 与 math.OC。分类及主题词统一配置在 `configs/app.yaml` 的 `sources.arxiv.search_scope`：`full_categories` 中的分类完整保留；`topic_groups` 中的论文需在标题或摘要命中该组任意关键词。匹配忽略大小写、连字符与换行，按词边界匹配，不要求出现 finance。先从日期索引定位目标批次，再分页取齐该批次的新论文和跨分类公告，排除单纯版本更新。列表保留最近 5 个公告批次，支持在此范围内补跑；目标日期超出保留范围、分页缺失或来源不可用时明确报告覆盖不足。公告日期直接使用列表批次日期，保留列表链接；不按美东发布日程补造精确时刻，不使用 API 首次提交日期或 RSS 更新时间替代列表日期。随后按编号批量取得完整摘要并固定返回的论文版本，查询接口失败时从官方摘要页补取，相关性达标后才下载该版本 PDF。东方财富取列表 `publishDate` 的日期部分，BigQuant 取集合 API `publishedAt` 的日期部分；来源原始值作为日期证据保存。手动后台检索仍可按原始发表/提交日期和显式结果数执行，区别于定时公告采集。

三个在线来源共用同一套候选日期范围校验，再进入统一的相关性筛选和下载流程。BigQuant 使用官网公开列表 API 的`publishedAt` 日期，按来源原始发布时间倒序分页，跨过起始日期就结束；直接取得标题、摘要材料和附件链接，不遍历历史详情页。单页容量只用于分页，不限制一天可采集的总篇数；日期、排序或分页证据异常会明确标记覆盖不足。

摘要不足时，只能复用库内同版本摘要或从已有正文提取摘要，**不会为了获取摘要而提前下载或临时解析 PDF**。仍缺材料的候选本轮跳过，等待来源补全或用户主动导入；缺材料与评分失败分别报告，不冒充低相关或正常完成。重复采集复用有效评分和全文，材料或规则变化后重新筛选。

本地 PDF 放入 `sources.local_pdf.library_path`（默认 `data/pdf_library/`）即可：服务启动后后台递归扫描新增或内容变化的 `.pdf` / `.PDF`，目录缺失时自动创建。成功导入且内容未变的文件通常跳过解析和模型调用；元数据版本升级会做一次不调用模型的日期/类型复查，失败项下次启动重试；运行中新增文件在下次启动时处理。启动导入只提取材料并分类，不做深度分析或推送，也不阻塞机器人连接。删除源文件不会自动删除库中记录；可设置 `import_on_startup: false` 关闭扫描。用户主动导入本地 PDF 或指定单篇阅读不受自动采集的相关性门槛限制。

本地论文优先提取完整摘要；缺摘要时用明确标注来源的引言进行分类，不把引言冒充摘要。日期依据原文明示的发表信息或出版元数据，保存来源、证据及日/月/年的真实精度；只有明确到日的发表日期进入报告日期字段，不补造月日或使用文件创建时间。分类标签保存引文和理由供核查，材料不足、规则分类与模型证据分类分别标记。

分类、相关性初筛、全文分析、证据评估与展示卡片共用后台服务及根目录 `skills/` 的固定任务资源。模型、材料或相关规则变化会使对应缓存失效；失败刷新保留原成功结果，过期结果不冒充当前有效评估。维护命令与详细策略见 [后台处理与维护工具](docs/architecture.md#后台处理与维护工具)。

## 安装与部署

### 本地安装

需要 Python 3.12；构建和检查网页需要 Node.js 22.13+ 与 npm（CI 使用 Node 22）。普通飞书聊天还需要运行账户的 `PATH` 中能找到可非交互运行的 `claude`，安装见 [Claude Code 官方文档](https://code.claude.com/docs/en/setup)。

在仓库根目录执行：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements/runtime.txt
cp .env.example .env                # 仅首次配置，已有文件不要覆盖
(cd frontend && npm ci)
mkdir -p data
claude --version
```

只运行机器人和单篇分析时，可改装 `requirements/bot.txt`；完整 Web 与调度器使用 `requirements/runtime.txt`。MinerU、Docling 为可选 PDF 解析扩展。

### 飞书应用与模型配置

在 [飞书开放平台](https://open.feishu.cn/) 创建企业自建应用并开启机器人能力：

1. 记录 App ID、App Secret，配置应用可用范围。
2. 选择长连接接收事件，订阅 `im.message.receive_v1`。
3. 开通接收用户消息、以机器人身份发送/回复消息所需权限；群聊还需相应群消息权限，代码也会尝试添加消息表情。具体配置参照官方[接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)说明。
4. 按平台要求发布应用版本；向群推送前先将机器人加入目标群。

长连接由本机主动发起，无需开放公网回调地址。首次配置可能需要先启动机器人，再回开发者后台保存长连接订阅。

编辑 `.env`：

```dotenv
FEISHU_APP_ID=cli_your_app_id
FEISHU_APP_SECRET=your_app_secret
FEISHU_ALLOWED_OPEN_IDS=ou_your_open_id
DEEPSEEK_API_KEY=your_model_api_key
DEEPSEEK_BASE_URL=https://api.deepseek.com/anthropic
CLAUDE_BOT_MODEL=deepseek-v4-pro
```

允许名单填写操作者的 **open_id**，多个用逗号分隔；空名单拒绝所有人，群聊也逐发送者校验。open_id 可由飞书开发者工具查询，或发消息后从本机拒绝日志确认；它与用于指定会话的 chat_id 用途不同。

| 模型路径 | 设置 |
|---|---|
| 飞书普通聊天 | `CLAUDE_BOT_MODEL`；机器人将 `DEEPSEEK_*` 映射给 Claude Code 子进程 |
| 分类、相关性初筛、全文分析与评估、复现准备 | Python 模型 API，读取 `configs/app.yaml` 的 `llm` 设置与 `skills/` 任务资源 |
| 日/周报排版、已有证据卡片展示 | 日报直接排版；周报调用配置的 DeepSeek 逐篇生成一句话结论，并附论文标题链接，推荐等级仍使用保存结果 |

### 启动与监听地址

```bash
bash start.sh --check                # 只检查入口 Python 依赖
bash start.sh                        # 构建前端，启动 Web + 飞书机器人
bash scripts/ops/run_bot.sh          # 只启动机器人
.venv/bin/python -m reportagent.main # 只启动 Web
```

默认网页为 `http://127.0.0.1:8000`。`start.sh` 在前台运行，Ctrl+C 停止它启动的子进程；端口被占用时退出。仅启动 Web 不接收飞书 WebSocket 消息；仅启动机器人不启动内置调度。配置或代码更新后重启对应服务。

监听参数由 shell 读取，需要导出或在命令前赋值，单写 `.env` 不生效：

```bash
ALPHAREPORT_BIND_HOST=127.0.0.1 ALPHAREPORT_PORT=8001 bash start.sh
ALPHAREPORT_PUBLIC_TUNNEL=true bash start.sh # 需安装 cloudflared
bash scripts/ops/sync_public_url.sh         # 同步临时隧道网址到 .env
```

公网隧道默认关闭。网页读取接口尚无完整登录认证，对外提供网页时应在部署层配置访问控制。

### 推送目标与详情链接

手动私聊 `/daily`、`/weekly` 直接发到当前会话。自动推送需在 `.env` 配置收件人和收件人可访问的网址：

```dotenv
FEISHU_DAILY_PUSH_IDS=oc_your_chat_id
FEISHU_DAILY_PUSH_TYPE=chat_id
FEISHU_WEEKLY_PUSH_IDS=oc_your_chat_id
FEISHU_WEEKLY_PUSH_TYPE=chat_id
ALPHAREPORT_BASE_URL=https://your-report-site.example
```

`open_id` 指定个人，`chat_id` 指定会话/群，多个目标用逗号分隔；会话 ID 可用 `/chatid` 获取。周报未设目标时复用日报的目标和类型，单独设置周报目标时使用周报类型（默认 `chat_id`）。详情网址必须能从收件人设备打开，本机 `localhost` 链接不适用于其他设备；已有消息中的链接不会随配置自动改变。

### 常驻与定时任务

服务持续运行时，后台的三项独立调度默认开启，时区均为 `Asia/Shanghai`。采集与日报每天执行，含周末；周报每周五执行。报告通过飞书机器人推送到配置的会话，不需要打开网页：

| 配置 | 默认时间 | 工作 |
|---|---|---|
| `daily_collection` | 每天 08:00 | 检查昨天全部来源条目，先相关性筛选再分类、入库和下载，最后完成全文质量评估，不发报告 |
| `daily_report` | 每天 09:00 | 从论文库生成日报，通过飞书机器人推送，不触发采集 |
| `weekly_report` | 每周五 09:00 | 从论文库生成周报，通过飞书机器人推送，不触发采集 |

在 `configs/app.yaml` 修改 `schedule_cron`（格式 `HH:MM`）或 `enabled` 后重启后端服务。周报的星期用 `day_of_week` 配置，`mon`、`tue`、`wed`、`thu`、`fri`、`sat`、`sun` 分别表示周一至周日：

```yaml
weekly_report:
  enabled: true
  timezone: "Asia/Shanghai"
  day_of_week: "fri"
  schedule_cron: "09:00"
```

三项任务可分别关闭；手动 `/daily`、`/weekly` 不依赖定时开关。只保留一个承载调度的后端进程，自动日/周报需有推送目标。周五 09:00 日报与周报都会运行，分别使用昨天、截至昨天的七天的资料范围。`/api/v1/health` 的 `schedule` 字段展示各任务开关及下次执行时间。手动执行同一采集流程：`.venv/bin/python scripts/collect.py`，不会发送报告。采集日志和回执记录起止时间、总耗时及元数据、相关性、分类、入库、下载解析、全文评估各阶段耗时。采集状态保存在 `data/collections/`，`latest.json` 是最近一次完成的记录。

测试其他报告日可运行 `.venv/bin/python scripts/collect.py --report-date 2026-10-17`：假定报告日是 10 月 17 日，采集其前一天 10 月 16 日的全部来源资料，继续完成筛选、下载入库和全文评估，不发送报告。该参数只改变本次采集的资料日期范围，不修改系统日期、定时任务或日志的实际执行时间；省略参数仍按北京时间今天计算昨天。重复运行会复用当前有效的评分和全文，不强制重新调用模型。

脚本结束后在终端逐源汇总元数据、相关性筛选、入库和全文获取结果，并列出各阶段耗时。全文阅读评估包含方法、发现、局限、质量与阅读建议，统计本次模型调用、完成数、有效缓存、缺材料及预算延期项；也会接续处理库中先前未完成的评估。新评估和缓存复用分开计数，空结果不会被说成完成了新分析。JSON 中 `storage` 只统计入库，`review` 保存阅读评估结果，不再输出与此流程无关的长篇研报 `analyzed: 0`。

需要持续开机的主机，并让运行账户能访问飞书、来源和模型接口、找到 `claude`。服务守护可使用：

```bash
bash scripts/ops/keepalive.sh
```

脚本检查服务 PID，必要时后台启动 `start.sh`，日志写入 `data/bot.log`；它不是模型或飞书连接的健康检查。后台常驻与开机自启不同，后者需配置 cron、launchd 或 systemd。

以下外部 cron **不会随仓库自动安装**。示例每五分钟检查服务；先替换工作目录和包含 `claude` 的实际 `PATH`：

```cron
PATH=/home/your-user/.local/bin:/usr/local/bin:/usr/bin:/bin
*/5 * * * * cd /absolute/path/to/AlphaReport-Claude && /bin/bash scripts/ops/keepalive.sh
```

如用外部调度替代采集、日报或周报，应关闭对应内置任务并重启后端服务，避免重复执行。已有外部周报定时任务也应移除，或将 `weekly_report.enabled` 设为 `false`。手动补跑、报告预览及可选预算命令见 [后台处理与维护工具](docs/architecture.md#后台处理与维护工具)。报告的 `--dry-run` 只读取已保存评估并预览，不调用模型或投递；日报会保存运行记录。

### Docker 部署

Docker 与本机共用 `start.sh`，一个容器运行网页后端和飞书机器人；后端提供构建好的 React 页面。镜像安装 Python 依赖与 Claude Code 并构建前端，服务器无需另装这些运行时。容器的 `deploy/claude-settings.json` 允许读取项目资料和执行列出的共享业务 CLI。

```bash
bash deploy/deploy.sh
```

首次运行创建 `/data1/alphareport/.env` 模板并停止。填写飞书凭据、允许名单和模型密钥，将 `ALPHAREPORT_BASE_URL` 改为其他设备可访问的服务器网址后，再运行同一命令。默认端口 80 可用 `http://服务器IP`，`PORT=8080` 对应 `http://服务器IP:8080`；有 HTTPS 反向代理时填其域名。部署检查拒绝缺失网址、`localhost`、回环地址和 `0.0.0.0`。

| 可覆盖变量 | 默认值 |
|---|---|
| `DATA_DIR` | `/data1/alphareport/data` |
| `CONFIG_DIR` | `/data1/alphareport/configs` |
| `BOT_STATE_DIR` | `/data1/alphareport/bot_state` |
| `ENV_FILE` | `/data1/alphareport/.env` |
| `PORT` | `80` |

部署默认使用执行者的 UID/GID，也可指定 `APP_UID`、`APP_GID`；挂载目录需允许该身份写入。首次部署复制仓库 `configs/app.yaml`，已有文件不覆盖。模型凭据变量名由 `llm.api_key_env`、`llm.base_url_env` 指定，应与环境文件一致。数据库、PDF、会话保存在宿主机挂载目录，网页和机器人共用数据库。

更新配置后重新执行部署脚本以重建容器、加载环境变量。健康检查只确认网页接口和机器人进程存在，真实模型调用与飞书连接仍需另行验证。查看日志：

```bash
docker compose -f deploy/docker-compose.yml logs -f
```

自行执行 Compose 时需导出与部署时一致的目录和端口变量。

## 维护与排查

### 日志与常见问题

- **飞书无响应**：检查进程、应用发布状态、订阅与权限、发送者允许名单，以及运行账户的 `claude` 路径、工具权限和模型凭据。`start.sh --check` 不验证外部接口联通。
- **分析或报告失败**：看 `data/report-jobs.log`；守护启动日志为 `data/bot.log`，隧道日志为 `data/cloudflared.log`，外部调度使用其指定日志。不能只凭“开始生成”判断任务完成。
- **有论文但日报为空**：核对昨天的日期范围、来源日期证据、当前方向评分与门槛、可用全文和评估状态；周报核对截至昨天的七天。`data/daily_reports/` 有最终状态与逐收件人结果，`data/collections/` 有来源与采集诊断。
- **PDF 或来源异常**：核对来源状态与 PDF 阶段日志。默认单次下载 45 秒、文字提取另限 20 秒、大小上限 25 MiB；可重试的网络错误最多请求 3 次，策略位于 `collection.pdf`。完整错误分类和补导、重分析工具见 [后台处理与维护工具](docs/architecture.md#后台处理与维护工具)。
- **迁移机器**：另行保存 `.env`、`data/`、`.claude-bot/` 及修改过的配置，重新核对凭据、目录权限与系统调度；重装依赖不会恢复历史数据。

### 本地 PDF 日期与材料类型

导入时保存原文支持的发表日期、精度与证据，以及独立于 `source=local_pdf` 的材料类型：学术论文、券商研报、社区研究、其他材料或类型未知。类型仅依据明确的文档头部/出版标识识别；无法判断时保持未知，不把本地 PDF 默认当论文。文件创建时间、导入时间和当前日期不会作为发表日期。

日报按昨天、周报按截至昨天的七天的来源 `published_date` 查询，均包含两端；显式 `--report-ids` 也使用相同日期范围。来源日期证据与精度保存在 `publication_date_info_json`，不会将文件创建、修改或入库时间当发表日期。本地 PDF 仅年份、年月或日期未知时继续保留在论文库，但不进入日报/周报。升级会根据已保存的来源原始证据迁移为日期并删除冗余公告时间列；升级前应备份数据库，缺少来源日期证据的旧在线记录保持未知。

升级先自动添加元数据列；旧的本地 PDF 文件指纹即使未变化，也会在下次启动导入时做一次元数据复查，不重复分类或调用模型。已确认日期/类型不会被一次无结果的解析清空，部分日期只在年月兼容时细化；此前误把引用语句识别为会议年份的记录，可由同一文档的明确发表日期证据纠正，已确认的有效日期仍予保留。只有已标明来源为文件创建/导入时间的旧日期才会被清除；无来源的历史日期不会被猜测性删除，可先备份数据库再人工核对。无法访问或解析的旧文件保留原记录，并在后续启动重试；没有原文件时无法自动补齐元数据。在线类型明确的采集源会在入库或升级时保存原有材料类型，日报/周报直接读取所存类型。
